<task type="auto">
  <name>Task 1: Create Supabase clients and API route pattern</name>
  <files>src/lib/supabase/server.ts, src/lib/supabase/client.ts, src/lib/supabase/middleware.ts, src/app/api/tasks/route.ts, src/app/api/tasks/[id]/route.ts, src/app/api/products/route.ts, src/app/api/products/[id]/route.ts, src/app/api/clients/route.ts, src/app/api/clients/[id]/route.ts, src/app/api/invoices/route.ts, src/app/api/invoices/[id]/route.ts, src/app/api/quotations/route.ts, src/app/api/quotations/[id]/route.ts, src/app/api/profile/route.ts, src/app/api/dashboard/route.ts</files>
  <action>
    Create `src/lib/supabase/server.ts`:
    - Export createServerSupabaseClient() that creates a Supabase client using SUPABASE_SERVICE_ROLE_KEY
    - Export getAuthUser(request: Request) that extracts Bearer token from Authorization header, verifies with supabase.auth.getUser(token), returns user or null
    - This pattern: API routes call getAuthUser() to verify the caller, then use createServerSupabaseClient() for DB queries

    Create `src/lib/supabase/client.ts`:
    - Export supabaseBrowser — client-side Supabase client using NEXT_PUBLIC_SUPABASE_URL and NEXT_PUBLIC_SUPABASE_ANON_KEY
    - Used ONLY for auth operations (login, register, get session token)
    - Never used for data queries

    Create `src/lib/supabase/middleware.ts`:
    - Helper to extract auth user from request and return 401 Response if not authenticated
    - Used by all API routes: `const { user, error } = await requireAuth(request); if (error) return error;`

    Create API routes following this consistent pattern for each entity:

    `/api/tasks/route.ts`:
    - GET: List tasks with optional query params (status, priority, assignee_id). Returns tasks with joined profile data.
    - POST: Create task. Validates body with Zod. Sets created_by from auth user.

    `/api/tasks/[id]/route.ts`:
    - GET: Single task by ID with checklists.
    - PATCH: Update task fields.
    - DELETE: Delete task.

    Same pattern for: products, clients, invoices (with invoice_items), quotations (with quotation_items), profile.

    `/api/dashboard/route.ts`:
    - GET: Returns aggregated stats (task counts by status, product count, unpaid invoice count, pending quotation count, monthly revenue).

    All routes: authenticate via requireAuth(), validate input with Zod schemas inline, use createServerSupabaseClient() for queries, return proper HTTP status codes and JSON.
  </action>
  <verify>`npx tsc --noEmit` passes. API routes export GET/POST/PATCH/DELETE handlers. All routes call requireAuth().</verify>
  <done>All API routes created with authentication, Zod validation, and Supabase queries via service role client.</done>
</task>

<task type="auto">
  <name>Task 2: Create React Query hooks and query keys</name>
  <files>src/lib/queryKeys.ts, src/hooks/useTasks.ts, src/hooks/useProducts.ts, src/hooks/useClients.ts, src/hooks/useInvoices.ts, src/hooks/useQuotations.ts, src/hooks/useAuth.ts, src/lib/api.ts</files>
  <action>
    Create `src/lib/api.ts`:
    - Export apiFetch(path, options) helper that:
      - Gets current session token from supabaseBrowser.auth.getSession()
      - Adds Authorization: Bearer {token} header
      - Calls fetch(`/api/${path}`, options)
      - Throws on non-ok responses with parsed error message
    - This is the ONLY way client components call API routes

    Create `src/lib/queryKeys.ts`:
    - Export query key factories: taskKeys, productKeys, clientKeys, invoiceKeys, quotationKeys, dashboardKeys
    - Pattern: `taskKeys.all` → ['tasks'], `taskKeys.list(filters)` → ['tasks', 'list', filters], `taskKeys.detail(id)` → ['tasks', 'detail', id]

    Create hooks following this pattern for each entity:

    `src/hooks/useTasks.ts`:
    - useTasks(filters?) — useQuery, calls GET /api/tasks with query params
    - useTask(id) — useQuery, calls GET /api/tasks/{id}
    - useCreateTask() — useMutation, calls POST /api/tasks, invalidates taskKeys.lists
    - useUpdateTask() — useMutation, calls PATCH /api/tasks/{id}, invalidates taskKeys.lists + detail
    - useDeleteTask() — useMutation, calls DELETE /api/tasks/{id}, invalidates taskKeys.lists

    Same pattern for: useProducts, useClients, useInvoices, useQuotations.

    `src/hooks/useAuth.ts`:
    - useAuth() — returns current user session from supabaseBrowser.auth
    - useLogin() — mutation calling supabaseBrowser.auth.signInWithPassword
    - useRegister() — mutation calling supabaseBrowser.auth.signUp
    - useLogout() — mutation calling supabaseBrowser.auth.signOut
    - useProfile() — useQuery for current user's profile via GET /api/profile

    All hooks use apiFetch() for data operations, supabaseBrowser only for auth.
  </action>
  <verify>`npx tsc --noEmit` passes. All hooks export properly typed return values. Query keys are structured consistently.</verify>
  <done>React Query hooks for all entities calling API routes via apiFetch(). Auth hooks using Supabase client auth. Query key factory for cache management.</done>
</task>
